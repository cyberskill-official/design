# Rà soát máy trạng thái / Implicit state-machine review

Phạm vi: thư viện component CyberSkill Design, Storybook, bộ UI kit và runtime template tĩnh trong kho này. Không có ứng dụng nghiệp vụ, máy chủ hay cơ sở dữ liệu để suy đoán thêm. Danh mục nguồn được sinh lại; bảng dưới đây là mô hình phục vụ rà soát, không phải chứng nhận mọi tổ hợp hành vi.

Scope: this repository's component library, Storybook, UI kits and static template runtime. [Source census](state-machines.md) · [JSON evidence](state-machines.json). The census includes files with no observations and fails on parse errors. It identifies candidate state storage, transitions and observable outputs; these overlap and **must not be counted as independent machines**. Aliased/dynamic calls, external applications and browser-native behavior need separate analysis. Test links below identify relevant regressions; a link is not a passing execution receipt.

## Quyết định / Decision

Giữ nguyên quyền sở hữu trạng thái, API, lớp CSS và các trục thiết kế. Không thêm thư viện máy trạng thái hoặc chuyển mọi component sang một bộ điều khiển chung. Chỉ sửa lỗi đã tái hiện và bổ sung danh mục có thể kiểm tra độ mới. UX được cải thiện bằng việc giữ focus khi kết thúc chỉnh sửa; DX và AX dùng cùng nguồn, vị trí dòng, biểu thức và hash thay vì dựa vào tên biến hoặc suy đoán từ ảnh.

Preserve existing state ownership, public APIs, DOM classes and independent design axes. Use the existing React/browser mechanisms, with explicit models and source discovery. No new state-machine dependency or blanket reducer migration: neither would establish compatibility. Correct the reproduced InlineEdit focus loss, and keep all other behavior intact. Model coupled transitions together; derive presentation from authoritative state instead of introducing another independently writable boolean.

## Thay đổi và kiểm tra / Change and verification

The only runtime change is InlineEdit keyboard completion. Before the change, a browser probe confirmed that Enter committed exactly one value but left `document.activeElement` on `body`. The replacement button is now focused in the existing browser-safe layout effect, before paint. Escape uses the same lifecycle rather than scheduling a late animation-frame callback. Blur does not request restoration, so it does not steal focus. The public declaration and generated prompt API stay unchanged.

`test:inline-edit-transitions` covers all 24 EN/VI × light/dark × ownership × nesting combinations in each of Chromium, Firefox and WebKit. It checks Enter, Escape, blur, IME confirmation and exact callback payload/count. It does not certify every element/contrast/viewport combination, native devices, React18 execution or manual assistive technology.

`test:state-inventory` checks AST/comment separation, controlled-only output discovery, HTML script locations, inert JSON scripts, template contents, CSS state selectors, fatal parse errors, canonical runtime inclusion, deterministic generation and current freshness. Run `node scripts/generate-state-inventory.mjs` after authored runtime edits; `--check` rejects stale output. These tests do not resolve a semantic transition graph.

Repository support approval is a separate machine: reviewed source → source changed → **unreviewed** → fresh operator review. InlineEdit's previous approval and exact hashes remain in lifecycle review history; the code change must not silently inherit that approval. Local test success does not grant support approval or publication authority. The operator subsequently gave explicit conditional approval in this chat to refresh only InlineEdit’s existing scope after the remaining functional and Linux visual checks passed. Those conditions were met and the exact-source support record was refreshed with its original history retained; no support scope was expanded.

Giới hạn: danh mục không chứng minh mọi đường đi hoặc mọi trạng thái có thể đạt được. Không tự phê duyệt hỗ trợ, không push, merge hay triển khai. Kết quả chạy kiểm tra và các cổng chưa đạt phải được báo cáo riêng với người dùng.
