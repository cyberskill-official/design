# Standalone mode documents

`modes/index.json` is CyberSkill's version 1 selection and provenance manifest. Each referenced file is an independent DTCG 2025.10 document containing concrete typed values. The index is not a proposed DTCG mode extension. Existing `tokens.json`, `tokens.js`, `tokens.dtcg.json`, declaration and native exports retain their compatibility contracts.

The 256 documents cover four theme/environment branches (light, dark, system with a light OS preference, system with a dark OS preference), the absence of an element plus all 15 authored element/variant packs, comfortable/compact density, and standard/high contrast. Attributes are co-located on one root. Arbitrary nested scopes, component interaction states, physical-device behavior, font metrics and CSS material composition are outside this projection. There is one style pack, liquid-glass, so it is recorded without inventing more style choices.

The authored portable-root inventory has 175 members. Three use relative `em` values and cannot be represented as DTCG dimensions without guessing the consuming font size. Each mode therefore emits 172 typed tokens. Nine additional CSS expression/identifier declarations were already explicitly excluded from the portable-root inventory. The resulting classified root inventory is 184 declarations: 172 typed plus 12 individually named omissions per mode. This is not a claim that all contextual CSS custom properties are portable tokens. Each omission records its reason and the resolved CSS expression; canonical CSS and `declarations.json` retain their authority.

The capture uses Playwright's installed Chromium, resolves the complete authored CSS import graph, loads the identical unmodified stylesheet after media setup (including Firefox’s contrast-emulation restyle boundary), waits for media/style updates, and preserves both operating-system branches of system theme. The index binds every CSS input and converter/validator to source hashes and records the exact engine, Playwright version, browser revision and capture platform. Capture uses screen media, a 1280×900 viewport, English root language, no reduced-motion preference and no forced-colors mode. These are recorded implementation conditions, not additional portable axes. No fonts or other network resources are fetched. `rem` dimensions remain `rem`; percentage numbers become dimensionless ratios. Colors retain sRGB or standard OKLAB components rounded to six decimal places, with at most 0.0000005 error per rounded component. The browser resolves the actual cascade and custom-property expression. For the authored `color-mix(in oklab, opaque-hex percentage, opaque-hex)` form, the existing pure OKLAB helper evaluates interpolation canonically instead of depending on platform-sensitive CSSOM rounding. Optional complementary percentages are supported only when the total is 100%; alpha mixtures, other spaces, unbalanced weights and unknown expressions fail closed. Actual rendered CSSOM colors are independently compared against these exported numbers in all three engines. OKLAB preserves mixes outside sRGB without clipping, gamut mapping or an invented hexadecimal fallback. DTCG explicitly defines OKLAB lightness in [0,1] and finite signed A/B components. See the [DTCG Color Module](https://www.designtokens.org/tr/2025.10/color/#oklab).

Run these commands after the regular token/source generators:

```sh
node scripts/generate-token-modes.mjs
node scripts/generate-token-modes.mjs --check
node _audit/ci/test-token-modes.mjs
node _audit/ci/test-token-modes-browser.mjs
```

Generation validates every document before writing. Unknown token membership, missing aliases, unsupported values and sources changing during capture fail closed. Stale source hashes, renderer versions, membership or generated bytes fail `--check`. Cross-platform checks retain the original capture-platform provenance but must reproduce every output byte using the same pinned renderer. A cross-platform pass is established only by actually running that check on the other platform; recording a platform does not establish it. The final canonical-mix batch passed all 256 byte-exact documents on macOS arm64 and the pinned Linux amd64 image `02bbb2155cd7` with networking disabled. Its receipt records the tested source/index identity; this does not establish other platforms or engine versions.

Browser checks compare every document against all three installed engines, test OS contrast branches and real source mutations, and write the measured color differences to `test-results/token-modes-browser.json`. Non-color values must match exactly. Different engine OKLAB calculations/serialization can differ slightly: the new cross-engine color check allows at most one sRGB 8-bit code point (1/255 per channel), records the actual maximum, and verifies that a deliberate larger mutation fails. The pinned Chromium freshness check remains byte-exact. This bound does not change existing accessibility, contrast or visual gates and does not imply cross-engine bit identity.

The original repository profile remains strict sRGB. The new mode profile explicitly opts into standard sRGB/OKLAB. The repository's Style Dictionary adapter accepts that same opt-in; callers importing legacy exports get the original default. To validate the real tool, separately install exact `style-dictionary@5.5.5` outside the repository without lifecycle scripts, then run:

```sh
node _audit/ci/test-token-modes-style-dictionary.mjs /absolute/path/to/style-dictionary
```

That test imports and exports all 256 documents through the CyberSkill DTCG/CSS adapter, including 240 with OKLAB values, and checks a second import for both system branches and contrast levels of the default Thổ pack. Its receipt records the exact tool version and primary-registry integrity metadata. This establishes that bounded adapter workflow, not arbitrary tool compatibility, native runtime mode selection or product acceptance. Latest released desktop-browser coverage and physical iOS Safari testing remain separate evidence.
