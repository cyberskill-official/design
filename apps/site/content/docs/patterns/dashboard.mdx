Use this shell for the home screen of a product: where people land after sign-in to see how things are going and jump to work. It combines [Side nav](/docs/components/side-nav), [Breadcrumbs](/docs/components/breadcrumbs), [Autocomplete](/docs/components/autocomplete) search, an [Avatar](/docs/components/avatar) account [Menu](/docs/components/menu), [Stat](/docs/components/stat) tiles with a [Sparkline](/docs/components/charts#sparkline), a [Line chart](/docs/components/charts#line-chart), a [Card](/docs/components/card) of recent activity and an [Alert](/docs/components/alert). Below 880px the side nav moves into a [Drawer](/docs/components/drawer).

## Notes

- Keep three to five KPIs. Each `Stat` says what changed and against what (`hint`); its sparkline gets a `label` that states the trend, so the tile reads without the picture.
- One primary action per screen. Here the page has none: "Export report" and "Upgrade plan" are secondary, so the quota alert does not compete with the data.
- The alert is part of the page from load, so it uses `role="note"` and is not announced as an interruption. Let people dismiss it.
- Responsive: the KPI row wraps to two columns and then one; the chart and activity card stack below 760px; the search moves to its own row in the top bar on phones. The layout uses container queries, so it adapts to the space it is given, not only the window.
- The account trigger is an icon button named "Account menu for Linh Tran"; the avatar inside it is `aria-hidden` so the name is not read twice.
- Do not put more than one chart in the first view on phones; link to the analytics page instead.
