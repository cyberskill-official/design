# Shared native template layouts

`scripts/template-shared-layouts-source.json` owns four bounded native style roles: footer links, invitation eyebrow, invitation title and invitation subtitle. The generator projects them into five existing templates: Culture Event Invite, Email, Marketing Launch, Marketing Newsletter and Tech Release Notes. Its 20 exact native owners comprise six invitation heading lines and fourteen footer links across English and Vietnamese.

The source map records each language branch, child-node path, native tag, non-style attributes and existing localized text or content expression. These are ownership guards. Copy, expressions, links, classes, conditional separators and all other document bytes remain authored in their current templates; the generator writes only the validated style attribute. A changed owner fails before any output is written. Native output and standalone/offline runtime behavior are retained.

Run `node scripts/generate-template-shared-layouts.mjs` after a deliberate role-style edit and `node scripts/generate-template-shared-layouts.mjs --check` to verify freshness. Do not change a path or copy guard to silence a drift failure without reviewing the actual owner. The tests compare the complete default source, rendered HTML, accessibility snapshot, screen and print pixels, DOCX XML/media and Chromium PDF text; a real shared-style mutation must reach every declared language owner. This bounded projection does not consolidate the remaining language-specific grammar or layouts.

Pixel checks remain exact when repeated original-source captures are stable. Each view first repeats the unchanged original input before capturing the projection. If pixels differ while that reference remains stable, only the original input is repeated further, with at most three reference captures in total. The test keeps full HTML, computed styles (including pseudo-elements), native/shadow geometry, accessibility and export comparisons strict. A reproduced original-reference pixel difference is reported as `unverified-reference-unstable`, with raw captures; it is not a pixel pass. A stable reference still requires exact projected pixels. No tolerance or browser-wide skip is used. WebKit has reproduced this reference instability for the static aurora background; no product or image workaround is justified by that evidence.
