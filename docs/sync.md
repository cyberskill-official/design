# Repository ↔ authoring environment — verified synchronization

Start from the repository snapshot selected for the task, and record its commit and local changes. A Git snapshot preserves its tracked file bytes. Successful restoration of compiler behavior, host integrations or editable exports requires separate evidence from the actual tools. An archive alone does not establish those capabilities.

Read [SKILL.md](../SKILL.md), [doctrine](./doctrine.md) and [consumer setup](./consuming.md) before choosing the runtime. Compiler sessions, including Claude Design sessions, are conditional authoring environments. Verify that the DC compiler and the requested import/export operations are available; do not assume `github_copy_files`, compiler recognition or a lossless round trip from a clone.

## Keep authored inputs and committed outputs together

Preserve the complete reviewed tree: CSS and token inputs, component JSX/declarations/prompts, authored card headers, templates and their runtimes, guidelines, kits, fonts, assets, docs, audit harnesses, package/lock files and host adapters. Preserve required license notices. A leading underscore does not determine whether a path is authored, generated, committed or transient.

| Deliverable | Ownership and regeneration |
|---|---|
| `_esm/react.mjs`, `_esm/react.d.ts` | Generated from the bundle export header by `scripts/generate-react-entry.mjs` (`npm run build:react-entry`). Edit the owning component contracts, then regenerate. |
| `_esm/cs.mjs` | Mixed ownership: the browser bootstrap before `export const VERSION` is authored; the version/export tail is generated by `scripts/generate-export-catalog.mjs`. `npm run build:exports` regenerates the catalog, bundle and React entries. |
| `_ds_manifest.json` | Components/cards belong to the export catalog generator; tokens/globalCssPaths belong to `scripts/generate-token-declarations.mjs`. Other fields retain their documented authoring/compiler ownership. Do not replace the whole manifest with an unrelated tool's output. |
| `_ds_bundle.js`, `dist/styles.min.css`, `DESIGN.md` | Committed consumer outputs. Regenerate with `npm run build:bundle`, `npm run build:styles` and `npm run build:design-md`. Generated does not mean disposable. |
| Token exports and native sample copies | `npm run tokens:generate` runs the complete repository token/export pipeline and synchronizes native copies. Source parity does not establish native compilation or device behavior. |
| Standalone runtime copies | Preserve the canonical vendor bytes and run the documented copy generators. Matching copies do not establish upstream authored source, redistribution rights or a complete runtime rebuild. |

`_esm/` and the committed consumer artifacts above must remain available to consumers. Consult `.gitignore` for the actual transient paths, including uploads, scraps, export proofs, dependency caches and Storybook/site build outputs. Keep private compiler graphs and review records outside public/npm payloads according to the publication policy.

## Import a session's work through a reviewed diff

1. Record the selected commit, `git status`, available tools and intended output. Preserve existing local work before importing another session's changes.
2. Export or copy the session to a separate directory. Compare its paths and hashes with the selected snapshot; inspect missing files, deletions and generated changes before applying a patch. Keep `.git/`, repository workflows and license notices under their existing ownership.
3. Apply only the authorized changes in a suitable local branch, normally `codex/<topic>`. Regenerate each affected output through its owner. Avoid editing two copies of the same contract independently and then overlaying both.
4. Inspect the complete diff and run the targeted checks plus `npm run test:unit`. Follow the [audit instructions](../_audit/README.md) for browser/pixel prerequisites. Test the actual imported runtime and the requested exported artifact separately; retain the source identity, commands, failures/skips and tool limitations.
5. Prepare the reviewed paths for a commit. Push, publication, deployment and merge require explicit operator authorization; a successful local check or a PR diff is not that authorization.

## Consumer boundaries

Static HTML consumers use `DESIGN.md`, CSS/classes and verified assets. Bundler React consumers use `_esm/react.mjs` with peer React and JSX transpilation. Legacy browser consumers use `_esm/cs.mjs` and `_ds_bundle.js`. DC authoring additionally requires the available compiler. Preserve and exercise the requested path rather than inferring equivalent support from copied files.

CyberOS orchestration and its two acceptance gates were retired on 2026-10-08. Product visual review, manual accessibility evidence and explicit release authorization remain separate requirements. A byte-matching copy, passing generator or successful local preview does not establish whole-system or human acceptance.
