# Quality gates — the benchmark reference

Every deterministic quality gate in the system, what it asserts, its pass criterion, whether it blocks (hard) or informs (advisory), and where it runs. Published on Storybook **Docs** at `design.cyberskill.world`.

**Where gates run.** *Fast board CI* = the `fast-gates` job in `.github/workflows/design-system-gates.yml`, which serves the repo and drives `_audit/run.html` headless via `_audit/ci/run-gates.mjs` (every push/PR + nightly + manual) — new board rows are picked up automatically. Two gates additionally run standalone as *merge blockers* (`docs-consistency-blocker` job, via `_audit/ci/run-single-gate.mjs`). *Whole-set CI* = the `whole-set-audits` job (every push/PR + nightly — owner decision B). *Unit test* = `npm run test:unit` in the `unit-tests` job (Node contracts plus Playwright browser, export and consumer tests). *Node pre-checks* = the `node-prechecks` job (browser-free authorities: bundle freshness, DESIGN.md freshness, styles.min.css + contrast-report freshness, manifest coverage) plus the `token-provenance` job. *Storybook CI* = the `storybook-build` job (`build:site` + `test:public-site` + freshness `--require`). Every browser gate publishes a verdict global (`window.__*`) that the headless runners read.

## Unit tests — `npm run test:unit`

The command combines Node checks with browser, document-export and packed-consumer tests. After `npm ci`, install Chromium, Firefox and WebKit with `npx playwright install --with-deps chromium firefox webkit` (Linux CI includes browser system dependencies). Most checks use Chromium; specific commands such as the documentation-count and focus regressions also run in Firefox and WebKit. A passing run certifies only each check’s stated scope and does not establish whole-system cross-browser, native OS IME or manual assistive-technology acceptance. ## Human-reviewed, never automated

- **Brand voice / copy** — warm · direct · honest · respectful is judged by a human, not a regex.
- **Legal template content** — counsel reviews the instruments; gates only check structure, bilingual mechanics, and print geometry.
- **Pixel-diff baselines** — Playwright `%` drift auto-fails (hard). After intentional redesigns, refresh `_audit/baselines/` with `pixel-diff.mjs --update` and commit. Side-by-side visual / component review pages stay advisory (judgment by eye).
- **Component API design review** — prop naming and ergonomics are reviewed by the owner, not asserted.
- **Manual AT (E1)** — NVDA / VoiceOver (and similar) checks are owner-attested; empty slots are not passes.

The built-in UI literal check now parses JSX child text and literal conditional, logical, template and array expressions with pinned Babel parser tooling. It rejects unregistered rendered English text in addition to the existing attribute scan. Exact exceptions are Editor B/I formatting glyphs (their action names are localized) and the Lumi proper name. It does not resolve variables, default props, translation completeness or runtime-generated text; browser locale tests and review remain required.

`npm run test:runtime-props` parses each public component export and compares explicit destructured prop names with the fresh compiler-derived API index, including inherited native props. It fails on unsupported source syntax instead of silently skipping exports. NumberField children is the sole intentional discard exception. This checks prop presence, not runtime type equivalence, rest-prop forwarding or semantic behavior.

The packed-assets check parses every packed JS/CJS/MJS/JSX file for literal imports, re-exports, require calls and `new URL(path, import.meta.url)` edges. Relative references must resolve to files, not directories. Computed edges are reported unresolved; bare module specifiers are counted separately and are not file-closure certification. Parser errors fail the check. A fresh legacy browser consumer must load local React and the component bundle from the extracted tarball with external requests blocked. This complements the image-slot runtime fixture; arbitrary computed URLs, JSX resource attributes and all runtime states are not certified by this scan.

Packed HTML inline scripts are also scanned when their type is absent, `module`, `text/javascript`, `application/javascript`, `text/ecmascript`, `application/ecmascript`, `text/babel` or `text/jsx`. Data and other script types are excluded. Inline module paths resolve relative to the HTML file. Missing-import and invalid-syntax probes must fail; JSON data blocks must remain unparsed. This scans dependency syntax without executing the inline programs or certifying every runtime resource.

`npm run test:font-rendering` uses Chromium platform-font inspection to reject system fallback for the defined Vietnamese repertoire in NFC and NFD forms. It is part of `test:unit`. The D82 font-subset repair passes the defined NFC/NFD repertoire on both source and flattened stylesheets, with no system fallback in the Chromium fixture. This does not certify every Unicode character, native platform or human visual acceptance. Static cmap coverage and `document.fonts.ready` are not sufficient rendering proof; do not normalize caller data silently to bypass the gate.
