# Component host semantics

Drawer uses a neutral `div` with `role="dialog"`, its existing localized or title-derived name and `aria-modal="true"`. `rootProps` targets that dialog div. The shared overlay manager continues to own focus trapping, Escape ordering, scroll locking and restoration. An `aside` landmark does not permit a dialog role override under [ARIA in HTML](https://www.w3.org/TR/html-aria/#el-aside).

Mentions keeps its native multiline `textarea` textbox semantics. The [textarea host rule](https://www.w3.org/TR/html-aria/#el-textarea) permits no combobox override. The input uses `aria-autocomplete="list"`, `aria-haspopup="listbox"` and, while suggestions exist, `aria-controls` and `aria-activedescendant`. Textboxes support these relationships in [WAI-ARIA](https://www.w3.org/TR/wai-aria-1.2/#textbox); `aria-expanded` is omitted because it is not a supported textbox state. A controlled listbox provides suggestion options. DOM focus stays in the textarea while ArrowUp/Down changes the active option and Enter inserts a mention. Options are outside the Tab sequence; Tab exits the widget. Escape closes suggestions. With no suggestions open, native multiline editing, including Enter for a newline, remains available. IME confirmation does not select a suggestion.

FormWizard step titles are informative content rather than disabled controls. All titles use full-opacity semantic text tokens; the current step has a heavier weight and `aria-current="step"`. The current/noncurrent distinction therefore retains visible and accessible state without attenuating informative text below the [small-text contrast requirement](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Navigation and validation behavior remain unchanged.

The regression captures accessible roles/names in Chromium, Firefox and WebKit, exercises focus and keyboard behavior, checks applicable axe rules without exclusions, and measures composed step-text contrast. It waits for existing finite CSS transitions to finish with motion enabled; transient mixed foreground/background colors are not reported as settled contrast. These automated checks do not establish manual assistive-technology acceptance.

Native field names and descriptions are separate. TextField, Textarea, Select, NativeSelect, Checkbox and Radio name their native controls from a stable owned label span, keeping supported hint/error text in `aria-describedby`. InputGroup also retains an explicit caller name with a visible label and supports numeric `0` labels. Existing native labels still provide click/focus behavior. Caller `aria-label` and `aria-labelledby` strings take precedence, including explicit empty/invalid strings; null/undefined attributes are omitted and allow the owned-label fallback. Caller and owned description references are merged without duplicates. Root/native refs, required/disabled/read-only behavior and native form values retain their declared contracts. This follows the [W3C guidance on names and descriptions](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/); no runtime fallback can repair an explicitly invalid caller name.
