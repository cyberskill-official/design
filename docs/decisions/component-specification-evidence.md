# Component specification evidence / Bằng chứng đặc tả thành phần

`components/specifications.json` inventories every public component against the canonical API and strict source-export parser. Generate with `node scripts/generate-component-specifications.mjs`; check with `--check`. The schema requires anatomy, slots, roles, states, keyboard and examples for every export, each with an explicit reviewed or unverified status. Unknown render expressions stay unsupported. No generated observation certifies behavior or accessibility.

Tệp đặc tả bao phủ mọi thành phần công khai theo API chuẩn và bộ phân tích nguồn nghiêm ngặt. Mọi thành phần có trạng thái rõ ràng cho cấu trúc, slot, vai trò, trạng thái, bàn phím và ví dụ. Biểu thức render chưa hỗ trợ giữ trạng thái chưa hỗ trợ; dữ kiện sinh tự động không chứng nhận hành vi hay khả năng tiếp cận.

JSX tags, attributes, spreads, key literals and parameter-reference expressions retain exact source spans. Spreads record unknown target/precedence; expressions are slot candidates, not approved slots. Class hooks retain their existing file scope. Canonical prop definitions are referenced rather than copied as a second type system. Native declaration availability still does not prove forwarding.

Thẻ JSX, thuộc tính, phép trải, phím và biểu thức giữ vị trí chính xác trong nguồn. Đích và thứ tự ghi đè của phép trải chưa được chứng nhận. Biểu thức chỉ là ứng viên slot; class hook giữ phạm vi toàn tệp. Định nghĩa prop tham chiếu API chuẩn thay vì tạo hệ kiểu thứ hai.

`scripts/component-semantics-source.json` owns a bounded reviewed fact in each of the six semantic categories for all 120 components, and 161 behavioral requirements across all 120 components. The 39 exports that had no requirement each map one named accessibility-gate case. Requirements map to exact named assertions. Every authored prop remains explicitly listed because a category fact is not a per-prop contract. Constructor presence in a named case is only a fixture reference; it is never sufficient coverage. `completeBehaviorSpecifications` counts exports whose anatomy, slots and examples are reviewed and that map a behavior-board assertion. `completeAccessibilitySpecifications` counts exports whose roles, states and keyboard facts are reviewed and that map an accessibility-gate assertion. Those counts are not a full prop matrix or manual assistive-technology acceptance.

Nguồn ngữ nghĩa có một dữ kiện đã rà soát có giới hạn trong từng nhóm của sáu nhóm, cho đủ 120 component, cùng 161 yêu cầu hành vi trên đủ 120 component. 39 export trước đây không có yêu cầu, mỗi export nay gắn một ca cổng trợ năng có tên. Yêu cầu gắn với khẳng định kiểm thử cụ thể. Mọi prop vẫn được ghi rõ vì dữ kiện nhóm không phải hợp đồng theo từng prop. Việc khởi tạo thành phần trong một ca kiểm thử chỉ là tham chiếu fixture, không đủ chứng minh độ bao phủ. `completeBehaviorSpecifications` và `completeAccessibilitySpecifications` đếm export đã rà soát nhóm tương ứng và có khẳng định trên đúng board. Hai số này không phải ma trận prop đầy đủ hay nghiệm thu trợ năng thủ công.

Capture actual execution with `node scripts/capture-component-behavior-evidence.mjs .`, then `node scripts/verify-component-behavior-evidence.mjs .`. The capture runs all named behavior and accessibility-board cases in Chromium, Firefox and WebKit, plus the existing three-engine field-association regression. The verifier requires exact source, bundle, CSS, test, assertion spans, case membership and engine membership. It rejects stale producers, failed/missing cases and duplicate engines. Passing output verifies only the mapped requirements on that recorded producer. It does not replace the full gate board, manual accessibility or release acceptance.

Chạy capture rồi verifier để ghi nhận thực thi trên ba engine. Verifier yêu cầu khớp nguồn, bundle, CSS, kiểm thử, vị trí khẳng định, danh sách ca và engine; dữ liệu cũ, ca thiếu/lỗi và engine trùng đều thất bại. Kết quả chỉ xác minh các yêu cầu được ánh xạ trên đúng bản nguồn đã ghi, không thay thế cổng kiểm tra đầy đủ, đánh giá trợ năng thủ công hay nghiệm thu phát hành.

G17 separately checks parameter-default assignability with the installed TypeScript checker and exact finite-union Storybook options. Native `keyof` domains are identified as derived domains rather than advertised as an exhaustive finite runtime matrix. Secondary-export fixtures can declare exact domains but must run their separate browser regression. `test-api-domains-browser.mjs` verifies every authored Icon SVG, both orientation key contracts, and FormField value/checked/pressed controller behavior. Its pressed case does not claim automatic Toggle field association.

No current named board case remains unmapped. The former weak HotKeys, InputOTP and focus-style cases were strengthened with application-state changes, controlled paste plus separate trusted typing/backspace, and native Button focus-visible checks; the outline-removal mutation is rejected. Aggregate/live-region, focus-spy and scrolling-spy cases keep those limitations in their authored requirement text. These are explicit gaps, not suppressed test failures.

Không còn ca có tên hiện hành nào trên board chưa được ánh xạ. Các ca yếu trước đây của HotKeys, InputOTP và kiểu focus đã được siết bằng thay đổi trạng thái ứng dụng, paste có điều khiển cùng kiểm tra gõ/backspace thật riêng, và focus-visible trên Button native; mutation xóa outline bị từ chối. Các ca dùng phép kiểm tra tổng hợp hoặc spy giữ giới hạn đó trong yêu cầu, không che giấu lỗi.

Runtime input membership is shared by capture and verifier: all bundle source modules, all current base/token CSS, the root stylesheet, both actual vendored React scripts, source maps, lock/package metadata and producer/server/freshness identities are required. Missing, unknown, absolute or traversal input paths are rejected before any receipt-directed file read. `parsedReceiptJsonSha256` hashes the serialization of the parsed receipt, not the original file bytes. This is local execution evidence; it is not an unforgeable attestation or human approval.

Capture và verifier dùng chung danh sách đầu vào chính xác, gồm mô-đun nguồn, CSS, React đã lưu, source map, metadata và bộ tạo/kiểm tra. Đường dẫn thiếu, lạ, tuyệt đối hoặc vượt thư mục bị từ chối trước khi đọc theo receipt. Hash JSON đã phân tích không phải hash byte của tệp gốc. Đây là bằng chứng thực thi cục bộ, không phải chứng thực chống giả mạo hay phê duyệt của con người.

Semantic excerpts may explicitly cite owned component/declaration/prompt files, directly named component stories, constructor fixtures, scoped named cases or transitive imported source utilities. Each explicit reference requires its reviewed SHA-256; emitted evidence records exact path, hash, ownership and source span. Unknown paths, traversal/absolute paths, symlinks, unrelated case scopes and hash drift fail. A story or fixture reference proves source presence only; execution remains a separate source-matched receipt. Passive or unresolved categories remain explicit rather than gaining invented interactions or stable part guarantees.

Trích đoạn ngữ nghĩa có thể dẫn tới nguồn, khai báo, prompt, story, fixture, ca có phạm vi hoặc utility được import thực sự. Mỗi đường dẫn tường minh yêu cầu SHA-256 đã rà soát; bằng chứng ghi đường dẫn, hash, quyền sở hữu và vị trí chính xác. Đường dẫn lạ, vượt thư mục, tuyệt đối, symlink, ca không liên quan hoặc hash thay đổi đều thất bại. Tham chiếu nguồn không chứng minh thực thi; phần chưa xác định giữ trạng thái rõ ràng, không tự tạo cam kết tương tác hay cấu trúc DOM ổn định.
