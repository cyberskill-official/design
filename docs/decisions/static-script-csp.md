# Exact script permissions for the static Vercel output

The authored authority is `scripts/site-deployment-policy.json`. After Storybook and the public allowlist are assembled, `scripts/vercel-static-output.mjs` parses each final HTML file and records its exact HTML hash, executable script hashes, and response policy in `public-site-csp.json`. The manifest follows `scripts/site-csp-manifest.schema.json`. Its source identity is derived evidence, not security approval or proof of deployment.

`scripts/lib/site-csp.mjs` parses browser-normalized script text with parse5. JSON data blocks and inert `text/x-dc` source are not granted execution permissions. DC source is interpreted by the existing runtime, which creates a script using the shared typed producer `scripts/template-runtime/dc-logic-source.mjs`. The builder hashes that exact wrapper, including its deterministic component token. `scripts/build-template-primitives.mjs --check` checks that the projected producer and every template runtime copy are current. Native template events use `data-cs-on-*` bindings interpreted into React listeners; native status preview forms register submit listeners. Unknown native handler attributes and JavaScript URLs fail the site build.

Known classified `text/babel` cards and kit pages are compiled only in final site output with the pinned local Babel runtime, matching its default react/env presets and plugins. Source HTML/JSX remains unchanged. Unknown attributes, custom presets, cross-origin/unclassified source, or separate Babel API usage fail closed. The now-unneeded transpiler loader is removed only from those transformed pages, and final ordinary script bytes receive exact hashes.

The generated Vercel Build Output API configuration contains exact HTML routes with their own hashes, index aliases with the same policy, and a strict no-inline fallback. Existing legacy redirects run first. Only generated directory indexes receive a `/directory` to `/directory/` redirect, preserving relative asset navigation; unrelated paths retain their existing behavior. Query strings do not change the selected policy. Redirects use the documented Build Output API `Location` header plus status. Query preservation is the local adapter contract and remains an explicit served-header check after an authorized Vercel deployment; this test does not certify the platform routing implementation. A local finite-route resolver exercises this generated subset in tests; it is not a complete Vercel emulator or evidence of deployed platform behavior.

Script policy grants same-origin files and exact script hashes. It grants no `unsafe-inline`, `unsafe-eval`, invented static nonce, `unsafe-hashes`, or CDN script origin. Existing style, image, font, connection, frame, worker, base and form controls remain intact. In particular, inline CSS remains allowed because the current components and Storybook use inline styles. This change hardens scripts, not every inline mechanism. Editor's separate restrictive content boundary remains unchanged.

The 4 KiB per-response CSP bound is a project budget, not a claim about a platform response-header limit. The generator also checks the current 2,048-route budget. Both fail closed. Rebuild after changing any HTML, the shared serializer, site policy, or Storybook inputs; do not copy hashes from an old release or grant a blocked runtime script merely to pass a test.

Required local validation is `node _audit/ci/test-site-csp.mjs`, a fresh `npm run build:site`, then `node _audit/ci/test-site-csp-browser.mjs` and the existing public-site browser checks. The CSP browser check validates every emitted HTML hash and alias, actual Storybook manager/story/docs, bilingual Markdown docs, all 85 built templates, interpreted native events and forms, and blocked unknown scripts and native handlers in Chromium, Firefox and WebKit. Build and browser receipts prove only the tested local bytes.

The root `_headers` file remains a legacy compatibility policy for hosts that support it. It does not express per-output HTML script hashes and is not the hardened Vercel policy. Other hosts need an explicit adapter that preserves each HTML route and alias policy, plus the same positive and negative tests. A plain server of `.vercel-static/` does not apply the manifest automatically. Publication and deployment require separate authorization; after an authorized deployment, verify real served headers, redirects and functionality before claiming platform acceptance.
