# Value pickers and expandable tables

The user selected a radiogroup default with explicit tabs mode for SegmentedControl. A small mutually exclusive value picker does not imply tab panels. The working tree therefore uses `mode="radio"` by default, with group/item roles `radiogroup`/`radio` and item `aria-checked`. Set `mode="tabs"` for the existing tab/panel composition: roles become `tablist`/`tab`, selection uses `aria-selected`, and caller option IDs and `aria-controls` continue to identify caller-rendered panels. The caller supplies a meaningful group name and manages values and panel visibility.

Both modes preserve the existing root ref, options/value/onChange data model, automatic arrow selection, orientation, wrapping, Home/End and native button activation. Composing, canceled and other-axis keys are left alone. The mode owns roles; arbitrary root role overrides cannot produce mismatched child semantics. Selected paint and forced-colors geometry use the same existing recipes for checked radio and selected tab states. No native radio inputs, form names, hidden values or new FormData serialization are introduced. See the [APG radio pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) and [tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/).

This remains a planned-major breaking default-role change. Prefer explicit `mode="tabs"` for existing tab/panel callers. The initial proposal also removed the inherited root role override; the owner subsequently selected retained deprecated semantic aliases `role="tablist"` and `role="radiogroup"`. An alias selects matching child roles only when `mode` is omitted; explicit `mode` wins, and unsupported role values reject. The prior removal proposal is archived separately and is not a current removal. This source revision does not bump `VERSION`, publish a notice, start a deprecation clock or authorize a release. Announcement date/version remain null. Any future removal still requires recorded notice spanning at least two published minor releases and at least 90 days, followed by a major release; all independent SemVer, support and release gates remain authoritative.

TreeTable keeps its declared native table with disclosure buttons and `children[]` data. It is not an APG treegrid. A treegrid entails a focusable row/cell keyboard model and additional hierarchy semantics; applying its role or hierarchy attributes alone would make a false contract. See the [APG treegrid pattern](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/).

The bounded TreeTable improvement exposes actual disclosure relationships: every visible data row has a stable per-table/key ID, and an expanded branch button's `aria-controls` lists its direct child rows. Collapsed, unmounted children are not referenced. IDs encode UTF-16 code units, including lone surrogates and punctuation, without serializing rendered ReactNode content. Existing globally unique node keys already identify expansion state; keyed reorder preserves child DOM and entered values. Native Tab and Enter/Space remain the keyboard contract. This does not claim ARIA level/position announcements, treegrid navigation or human assistive-technology acceptance.
