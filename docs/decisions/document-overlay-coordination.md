# Overlay coordination across compiled copies

The document owns one stack for compatible current CyberSkill runtime copies. Independently compiling two copies must not create two Escape listeners, competing inert state or separate scroll ownership. The prior module singleton did so: a single native Escape invoked both independently registered dismissals. Source-bound multi-bundle regressions retain that failure.

The manager and ownership-context registry now live on the current `document`, under the private `Symbol.for("@cyberskill/design/overlay-manager")` key. The exact private protocol is `cyberskill.overlay-manager/1`. A mismatched protocol, accessor record or missing required manager/context capability throws before registration. The record cannot be replaced through ordinary assignment. This is runtime coordination, not an HTTP API or a security boundary against scripts already controlling the document.

Compatible copies use one manager for ordering, top-only Escape, IME guards, inert/background isolation, scroll restoration and logical focus scopes. Context identity is shared for the same React peer instance, so React ownership crosses both compiled-module and portal boundaries. Different React peer instances may coordinate separate roots through the document manager; mixing their hook trees is unsupported. Provider markers are empty bookkeeping elements, not automatic portal destinations. Client layout allocates document-unique marker IDs, skipping existing IDs. Server output and the first hydration render omit the IDs; ordinary rerenders retain them. StrictMode cleanup is supported.

There is no document registry during server rendering. Each server module receives a DOM-free fallback and ordinary server contexts; imports and rendering do not mutate a process-global or cross-request stack. Requested floating content retains its separate SSR contract. Automatic native form/fieldset inline fallback is preserved across current compiled copies; no form ownership is inferred from an opener. See [floating panels](../floating-panels.md).

Tests compile two actual source bundles independently, then exercise real nested Dialog/AlertDialog ownership, a body Popover from the other copy, native form/disabled-fieldset behavior, top-only and composition-safe Escape, Tab containment, opener restoration, dynamic inert branches, prior inert/overflow value and inline priority restoration, unique provider markers and cleanup. They also reject incompatible protocol/capability fixtures before DOM effects. Matching React 18 and 19 development SSR/hydration checks cover multiple independently compiled providers. Layer cleanup uses registration identity, so reused caller IDs cannot remove another registration; generated layer IDs avoid live caller-ID collisions.

All loaded copies must implement the compatible protocol. Old unversioned bundles cannot be retroactively enrolled, and silently mixing them is unsupported; rebuild every runtime copy. A protocol change requires explicit compatibility review. This does not add independent manager scopes, shadow-root/iframe focus coordination, physical native-popup or IME acceptance, or human assistive-technology acceptance. Each separate document has its own registry.
