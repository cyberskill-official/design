# Additive token spelling compatibility

The 22 kebab-case names own the concrete values, for example `--cs-component-button-md-padding-x: 20px`. The previously published camelCase names read those owners, for example `--cs-component-button-md-paddingX: var(--cs-component-button-md-padding-x)`. Overriding the kebab name updates both spellings. Overriding only the camelCase name shadows that spelling and leaves the kebab owner unchanged. Density scopes set the kebab literal and point the camelCase name at it, so compact, comfortable and nested resets stay consistent. Native identifiers are unchanged: the camelCase constant keeps its established name, and the kebab constant keeps the `Alias` suffix with the same number.

`tokens/base-inventory.json` declares every alias/type. Its `com.cyberskill.nativeAliasOf` and `nativeName` extension explicitly distinguish new native identifiers, such as `componentButtonMdPaddingXAlias`, from established identifiers. Both names retain the same resolved numeric value; all established Swift, Kotlin and Dart constant lines remain unchanged. Unreviewed identifiers or collisions fail generation before outputs are written. Portable DTCG values use ordinary intra-document references, with the compatibility mapping retained as namespaced metadata.

Each standalone mode document contains its own referenced legacy leaf. The exact resolved source CSS is recorded as `resolvedSourceCss` when different from `css`; otherwise its value is exactly `css`. This lossless default avoids duplicating identical strings under the existing mode artifact budget. Captured alias values must equal the referenced legacy value in every mode. This introduces no external token dependency or DTCG mode extension.

Validation: `test-token-legacy-aliases.mjs` preserves all original declarations; `test-token-legacy-aliases-browser.mjs` compares 22 pairs across 256 modes and nested density scopes in three engines; `test-token-native-aliases.mjs` checks original constants, numeric aliases and fail-before-write collisions; `test-token-mode-aliases.mjs` verifies exact source reconstruction and alias-drift rejection. These are bounded compatibility checks, not native compiler/device or design-tool certification.

The element generator now emits unconditional root accent defaults, existing aurora presentation rules and the scope resolver. Superseded scoped literal blocks are removed only after exact public-token and consumed-paint comparisons across 4,096 co-located/inherited/reset cases per engine. The frozen former source is `_audit/ci/fixtures/a01-elements-before.css`. `test-element-version-ownership.mjs` also verifies that the emitted CSS exactly matches this reviewed projection. Dark/system declarations in three CSS files are now checked value mirrors of `tokens/theme-palette-source.json`; their selectors, order and all adoption bytes remain unchanged. The resolver continues consuming those exact CSS blocks after freshness verification.

The existing public `element-seeds.json` `$meta.version` field remains present. It is now a checked/generated projection of `VERSION`, as are the existing export release fields. Palette seed data and every other seed metadata field remain authored and unchanged. Mutating either the stale seed stamp or `VERSION` proves that regeneration restores the single version authority without changing palette CSS. No published token name, native identifier or public metadata field is removed.
