## 1. Executive summary

Scoring criteria: each score is evidence-based against the named checks; 10 requires zero findings at that layer plus proactive coverage. Scores are directional engineering judgments, not certifications.

| Dimension | Score | Basis |
|---|---|---|
| **Overall UX maturity** | **6.5 / 10** | Flows are coherent and brand-distinct; flagship surfaces polished; but a systemic contrast pattern, sub-390 breakage, and artifact-level a11y gaps ship today |
| **Accessibility maturity** | **6 / 10** | Component-level ARIA/focus/reduced-motion/forced-colors genuinely strong (all verified live); artifact level (titles, lang, landmarks, skip links) and several widget keyboard models (CDS-A11Y-003) unresolved; no manual AT evidence |
| **Design-system maturity** | **7.5 / 10** | Token pipeline, four-axis model, and 32-gate verification culture are top-decile; role gaps (`on-strong`, depth), an untokenized document palette, and off-ramp type sizes hold it back |
| **Responsive quality** | **7 / 10** | Whole-set 390/VN/dark passes are real and rare; 320px (WCAG reflow width) breaks 6 surfaces and 5+ component patterns; 1920 mostly disciplined |
| **Enterprise readiness** | **5.5 / 10** | UX side: no skip links/landmarks on app surfaces, runtime React from unpkg CDN, default Storybook branding on the product site; release-engineering side per CDS register (score 2.10/5 there) is the deeper blocker |

**The five biggest problems**

1. **Text-on-`accent-strong` is a systemic contrast failure in light mode** — 169 axe serious nodes across 31 pages. Worst cases: all four deck templates put ochre `accent-bright` headlines on `accent-strong` gold covers (measured 2.15:1, including the 64px "Turn Your Will Into Real" title slide) — the documented doctrine says deck covers are *umber*; and the lawyer-validated `vn-disciplinary-schedule` renders sanction-level codes HT1–HT4 in ochre-on-white at **1.76:1, 12px** — the legally decisive cell content is the least legible thing on the page. The dark-mode equivalent is gated (`theme-overflow`); light mode has no DOM contrast gate, which is exactly where this lives. **NEW** (extends CDS-TOKEN-002).
2. **Template artifacts ship without `<title>` and `<html lang>`, and product screens lack landmarks and skip links** — 84/84 templates flagged (axe serious ×86/×84); Dashboard, Settings, Sign-in, Article have no `<main>`/`<nav>`; zero skip links anywhere (kits included). In the authoring host this is masked; in the copy/export/standalone path — the product's whole point — it ships. **NEW**.
3. **320px reflow breaks core components and kit pages** — Dashboard clips KPI/progress content (28px overflow), Status Hub settings hides the third tab with no scroll affordance (135px), kit cards force 330px, kitchen-sink 182px, plus component-level offenders (Tabs strip, Pagination, InputOTP, DescriptionList, `.cs-field` min-width). The house gate proves 390, not 320 (WCAG 1.4.10 reflow width). **NEW** (concretizes CDS-CONTENT-001).
4. **Bilingual doctrine leaks at the edges** — flagship `marketing-page` in Tiếng Việt still renders the English PromptInput hint "Lumi replies, then hands clear wishes to a human." (the VI string exists in the registry; language resolution misses it — and the `template-lang-parity` leak lexicon doesn't contain it); `auth` mixes EN+VN in one line in EN mode ("Welcome back. Đăng nhập để tiếp tục."); `image-slot` ghost text is EN-only; DataGrid's pin control is hardcoded English with a `⟂` unicode glyph (doctrine forbids glyph icons). **NEW** (adjacent to CDS-I18N-001, CDS-ICON-001).
5. **Theme/focus/target consistency debt confirmed live** — system-theme dark leaves `[data-theme="dark"]`-scoped component fixes unapplied (CDS-THEME-001 confirmed at HEAD); focus rings render 2px on some controls and 3px on others in the same tab walk (kit switch inputs show a 2px UA-ish ring); Status Hub settings has 4 unlabeled switches (name/role/value fail); Carousel dots fail WCAG 2.5.8 24px minimum; `.cs-dialog-layer` hardcodes z-index 1000, inverting the documented depth scale so toasts (200) render *behind* dialogs. Mostly **confirmed CDS-A11Y-004/THEME-001**, z-order inversion **NEW**.

**The five strongest existing qualities** (preserve these)

1. **Verification culture.** 32 deterministic hard gates + three whole-set state audits + 11 unit tests, all green, manifest-driven, race-aware, with vendored axe. Very few design systems of any size have this. Every fix below should land with a gate extension, in this same idiom.
2. **Brand coherence.** The umber/ochre/aurora/Lumi identity is distinctive and consistently executed on the flagship surfaces (website kit hero, marketing page, A4 instruments). The warm palette discipline ("every neutral warmed toward umber") visibly holds.
3. **The bilingual A4 legal suite.** 37 lawyer-validated Vietnamese-first instruments with Ink/Slate pairing, state-motto headers, signing blocks, PDPL hygiene — clean at 390, clean in print smoke, professional on screen. This is a genuine moat.
4. **Token architecture breadth.** CSS vars + JSON + ESM + DTCG + native mirrors with provenance pinning and byte-level parity gates; four orthogonal axes actually implemented and demo-able live (Storybook toolbar renders Theme × Element × Language × Style).
5. **Component-level a11y baseline.** The a11y interaction gate's 22 assertions (focus traps, roving tabindex, activedescendant, live regions), reduced-motion collapse (0 running animations under emulation), and forced-colors focus survival all verified live in this audit.

**Highest-leverage improvement.** Define the missing **"text on accent-strong" role** (`--cs-accent-on-strong`, guaranteed ≥4.5:1 in light *and* dark for every element×variant pack) and re-point the deck covers, band headers, and badge patterns at it — then extend `contrast-guard`'s token-pair matrix to cover `on-strong` in light mode and add the light-mode DOM walk. One token role + one gate row retires the largest defect class (169 nodes/31 pages) at the root, in the system's own expansion-rule idiom. Second highest: a template head standard (title + lang + main/skip) applied by the compiler/`ds-base.js` so all 84 artifacts inherit it in one change.

## 3. End-to-end flow audit

Flows are the design system's own product flows; per-flow friction is deep-dived in §4 findings referenced by ID.

### 3.1 Adopt the system (agent or developer)
Entry: repo root / npm / llms.txt. Goal: first on-brand artifact or component render.
Steps: llms.txt → SKILL.md or DESIGN.md → link `styles.css` → mount bundle/React entry.
What works: audience-mapped front doors are unusually clear; one-file CSS promise holds; `examples/` prove both paths; prefix-resolve namespace rule is documented everywhere it needs to be.
Friction: **styles.css is a 24-import chain** (~156KB unminified CSS) — serial `@import` delays first paint for every consumer (CDS-PKG-003 confirmed; perceived-performance item UX-027); **runtime React from unpkg** contradicts the self-hosted doctrine and fails air-gapped/enterprise networks (UX-026); React entry needs consumer transpilation (CDS-PKG-001).
Acceptance: a new consumer reaches a rendered Button in <30 min on a clean network *and* offline; flattened single-file CSS ships; React vendored beside the bundle.

### 3.2 Build an artifact from a template (the core product flow)
Entry: Templates picker / `templates/<slug>/`. Goal: branded, bilingual, exported document.
What works: copy-folder + one-line rebind is real (subtree test green); axes tweak live; print docs paginate cleanly (print-smoke green); VN survives PPTX/standalone export (`_audit/exports/`).
Friction: exported/standalone artifacts inherit **no title/lang/landmarks** (UX-002); light-mode contrast class (UX-001) ships in decks and several docs; **PromptInput hint stays EN in VN mode** on marketing-page (UX-004); image-slot ghost hint is EN-only and visibly overlaps hero copy at 1440 (UX-013); deck covers regressed from umber doctrine (UX-001a).
Acceptance: an exported standalone/PDF passes axe serious=0 for title/lang; VN mode renders zero EN strings outside the canonical lockup; deck cover uses ink/umber surface with AA-passing title.

### 3.3 Compose product UI (npm consumer)
Covered deeply by CDS register (TYPE/PKG/API/FORM/ARCH). UX-lens additions: dialog-over-toast z-inversion (UX-009) will bite any product that toasts on save inside a modal; system-theme consumers hit THEME-001; DataGrid pin control is EN-only with a glyph icon (UX-007).
Acceptance: depth tokens govern all layers; toast visible above open dialog; pin control uses `Icon` + registry strings.

### 3.4 Sign in (auth template as the product's auth UX)
Works: split-panel brand + form, labeled fields, escape hatch ("Talk to Lumi instead"), no self-signup ("Ask for access") — right enterprise posture. Clean at 390.
Friction: subtitle mixes EN+VN in one line in EN mode against the fully-separated language decision (UX-014); "Remember me" defaults ON (UX-015); password reset path absent (by design? unstated).
Acceptance: language-pure strings per mode; remember-me default off or policy-documented; reset/contact path stated.

### 3.5 Operate a portfolio (Status Hub kit + dashboard template)
Works: KPI → lenses → drawer pattern is legible; board/table toggle clear; 390 clean.
Friction: 320 clips tabs and card content (UX-003); 4 unlabeled switches in settings (UX-006); hand-rolled `.cs-tab` markup diverges from the real Tabs component and mis-declares ARIA (UX-005); card grid min-width 330 (UX-003b); 1227px-wide release-notes text at 1920 (UX-024).
Acceptance: kit pages compose real components or match their ARIA/keyboard contract exactly; 320 clean; text measure ≤ ~75ch.

### 3.6 Marketing visit → wish (website kit / marketing-page)
Works: hero is excellent — identity, bilingual toggle, dark toggle, wish input with disclosure hint; VN swap covers nav through cards.
Friction: four "Talk to Lumi" affordances visible in one viewport (header, hero secondary, FAB; plus "Make a wish" primary) — competing CTAs (UX-016); VN-mode EN hint (UX-004); ticker band link contrast borderline on umber (advisory).
Acceptance: one primary + one secondary CTA per viewport; FAB deduped or contextual; VN pure.

### 3.7 Maintain and expand (owner/agent)
Works: expansion rule + gates make regressions loud; `_audit/index.html` is a real console; conventions doc is precise.
Friction: no light-mode DOM contrast gate (the exact hole UX-001 lives in); 390-only overflow gate; `docs-consistency` doesn't watch `storybook-static` freshness vs stories (UX-030); depth tokens partially enforced (UX-009).
Acceptance: new gates per §9 land with fixes; static-build freshness pinned to stories tree hash.

## 4. Screen-by-screen findings

Format: Evidence → Impact → Recommendation → Priority / Effort / Confidence → Acceptance. "Confirmed" = reproduced in this audit with the probe/screenshot named. Cross-refs to the CDS register where applicable.

### UX-001 · Text on `accent-strong` fails contrast across light-mode surfaces — **Critical / M / Confirmed** · NEW
Location: all 4 deck templates (`slide-deck`, `bod-deck`, `sales-proposal-deck` — 4 sections, `delivery-qbr-deck`), `marketing-newsletter` header+footer bands, `marketing-page` footer band + chat CTA, `dashboard` header band, `finance-*` headers, `hr-announcement`, `tech-*` emails — 31 pages, 169 axe serious nodes (probe JSON).
Evidence: axe pairs measured — `#F4BA17` on `#A47D17` **2.15:1** at 14–64px (deck eyebrows, slide numbers, cover H1 "Turn Your Will Into Real"; screenshot `slide-deck-cover.png`); `#FFFFFF` on `#A47D17` **3.8:1** at 13–16px (band titles "The Lamp", dashboard subtitle 3.02); `#45210E` on `#A47D17` **3.74:1** (CTA "Make a wish"/"Read the story"); cream `#F1ECDC` on strong **3.21** at 13–14px. Template source: `templates/slide-deck/SlideDeck.dc.html:17,52,58` — `background:var(--cs-accent-strong);color:#fff`.
Problem: `-strong` is documented as the *accent text on light* role ("APCA-validated, WCAG-borderline… reserve for semibold/large accent text", conventions §Dark-theme contrast) but is used as a *background* under normal-size and ochre text. Light packs define no `on-strong` guarantee (dark packs do — cream on strong ≥75 APCA, per `theme-overflow` doctrine). The light-mode hole is structural: `theme-overflow`'s DOM contrast walk runs only in dark; `contrast-guard`'s matrix doesn't score text-on-`-strong` in light.
User impact: deck covers — the first slide every client sees — are visibly muddy gold-on-gold for the *default* element (Thổ = the studio itself); READMEs promise "umber title + closing". Emails/bands lose header legibility for low-vision users; brand slogan illegible at its most prominent placement.
Recommendation: (a) add `--cs-accent-on-strong` to the 9-token pack contract (making it 10) with generated values passing ≥4.5:1 on `-strong` in light and dark for all 15+15 packs (`scripts/generate-element-packs.mjs`); (b) re-point band/badge text at it; (c) restore deck covers to the documented umber/ink surface (`--cs-color-brand-umber` bg, ochre accents ≥ large-AA) — element identity stays in the accent bar/gradient, not the whole cover; (d) extend `contrast-guard` matrix + add a light-mode DOM walk row mirroring `theme-overflow`.
Acceptance: axe serious color-contrast = 0 across all 84 templates at 1280 light EN; `contrast-guard` scores `on-strong` light+dark for all packs; deck covers match doctrine visually (baseline regenerated intentionally).

### UX-001a · `vn-disciplinary-schedule` sanction codes HT1–HT4 at 1.76:1 — **Critical / S / Confirmed** · NEW
Location: `templates/vn-disciplinary-schedule/` sanction-level table cells (20 axe nodes).
Evidence: `#F4BA17` on `#FFFFFF`, 12–12.5px bold (screenshot `disciplinary-ht.png` — codes visibly faint).
Problem/impact: the legally decisive cell content (sanction level per violation) is the least legible text in a lawyer-validated disciplinary instrument; near-invisible in grayscale print. Content is verbatim-locked; presentation is not.
Recommendation: restyle code badges to Ink/umber text (optionally ochre *background* chip with umber text ≥7:1); keep content verbatim. Sweep the other 36 `vn-*` instruments for ochre-as-text-on-white (probe JSON lists none as severe — confirm in fix PR).
Acceptance: axe serious = 0 on the instrument; codes legible in grayscale print smoke.

### UX-002 · All 84 templates ship without `<title>`/`<html lang>`; product screens lack landmarks; no skip links — **High / S–M / Confirmed** · NEW
Evidence: axe `document-title` ×86, `html-has-lang` ×84 (every template; kits/guidelines have them). Landmarks probe: `<main>` in 2/84 templates; Dashboard `{main:false,nav:false}`, Settings/Sign-in all-false, App shell has main+nav+banner. Skip links: 0 repo-wide (grep + rendered).

### UX-003 · 320px reflow breaks pages and component patterns — **High / M / Confirmed** · NEW (concretizes CDS-CONTENT-001)
Evidence (overflow @320, culprit probe): Dashboard 28px (project-row inner min-width — % value clipped, screenshot `dashboard-320.png`); Status Hub settings 135px (tab strip, third tab hidden, no scroll affordance — screenshot); Status Hub index 34px (`button.card` min-width 330); Website work 24px (`article.case`); kitchen-sink 182px (`.cs-field` ~227px floor, `dl.cs-dl` two-col, alert grid); type-scale guideline 120px (absolute specimens). Acceptance: whole-set overflow gate green at **320 and 390**; the six named surfaces render 0 document overflow at 320; tabs reachable by scroll at 320.

### UX-008 · Timeline marker: white-on-semantic breaks in dark — **Medium / S / Confirmed** · NEW

### UX-009 · Depth scale broken at the top: dialogs hardcode 1000; toasts (200) render beneath — **Medium / S / Confirmed** · NEW
Evidence: `base/components.css:133` `.cs-dialog-layer{z-index:1000}` vs `tokens/elevation.css` modal=100 < toast=200 (comment: toasts above modals). Also `--cs-depth-dropdown`(×8)/`--cs-depth-overlay`(×2) consumed with fallbacks but **not defined** in the token layer; fallback drift `var(--cs-depth-modal, 90)` vs token 100 (`base/controls.css:168,271–273`).
Impact: a toast fired while a dialog is open (save confirmation in a modal flow) is invisible; dropdown z ties nav z=50 (DOM-order-dependent overlap under sticky nav); token viewer/docs advertise a 6-step scale the CSS doesn't follow.
Recommendation: define `--cs-depth-dropdown:60`(+overlay) in `elevation.css`; dialog layer uses `var(--cs-depth-modal)`; decide and document toast-vs-modal order (toast above, per the token comment); extend `token-contract` to assert every `--cs-depth-*` consumed is defined and every z-index in `base/` is token-driven.
Acceptance: gate asserts zero undefined depth tokens and zero raw z-index >20 in `base/`; toast visibly stacks above an open dialog in behavior test. (CDS-ARCH-001's layer manager is the deeper fix; this is the containment.)

### UX-010 · System-theme dark leaves component-state overrides unapplied — **High / M / Confirmed** · = CDS-THEME-001 (re-verified at HEAD)

## 5. Design system audit

**What exists and is strong.** 446 tokens across 10 concern files with generated JSON/ESM/DTCG/native mirrors and provenance pinning; four orthogonal axes implemented end-to-end; 15+15 element packs generated from seeds with APCA-derived dark values; component contract trio ×105 with cards and prompts; 32-gate verification board; logical-properties RTL-ready base; self-hosted VN-subset fonts with an integrity gate; a central bilingual string registry with a parity gate.

**Gaps and inconsistencies (root-cause level).**

1. **Missing role tokens where usage already exists** — `on-strong` text role (UX-001), `depth-dropdown`/`depth-overlay` (UX-009), document palette (UX-021), semantic-fg pairs for literal-on-semantic patterns (UX-008). The pack contract should grow to cover every pairing templates actually use; the guard matrices then enforce them. This is the single most valuable structural change.
2. **Raw-value drift in base** — 34 off-ramp font sizes incl. fractional and 11px (UX-022); 84 hex literals in `base/` of which most are legitimate fixed pairings but at least two (timeline marker, dialog z) are live defects; CDS-TOKEN-002's 378 raw-color count stands.
3. **Two focus-ring recipes** (UX-023) and **two tab implementations** (component vs hand-rolled kit/sink markup, UX-005) — consolidation, then a gate that greps reference surfaces for `.cs-tab` without `role="tab"`.
4. **i18n registry at 45/105** with no coverage rule for built-in strings (UX-020, UX-007).
5. **Icon grammar bypasses** — `⟂` in DataGrid; local SVGs in FileUpload/Image match the line-icon style but live outside `CS_ICONS` (CDS-ICON-001). Migrate to registry entries so RTL-mirroring metadata can attach later.
6. **Duplication is otherwise low** — no near-duplicate components found; sub-part co-export pattern is clean; naming grammar is consistently applied (spot-checked across 30 files).

**Missing states/variants (survey).** Components broadly ship default/hover/focus/disabled/loading/invalid where applicable (stories `--states` exist; behavior gate covers 78 interactions). Systemic omissions: no `error`/`empty` guidance for Chart/DataGrid loading models beyond skeleton; Toast lacks an action/undo slot (undo doctrine currently unstated system-wide); FileUpload lacks progress/error states (CDS-A11Y-002 scope).

**Migration strategy.** Additive-first (new tokens/roles land beside old usage → codemod-style sweeps per surface → guard flips from advisory to hard), exactly matching the house expansion rule; no big-bang rewrite is warranted by the evidence — CDS-ARCH-001's overlay layer is the only architectural rebuild justified, and it should follow the CDS plan's phasing.
